## How the rubric was adapted

The `seo-review` skill was written to audit JavaScript tutorial pages. Its 7 categories and 30 points are kept, but checks that only make sense for tutorials were swapped for local-business equivalents. A check that doesn't apply to a page counts as a pass, following the skill's "(if applicable)" wording.

| Skill's original check | Used here instead |
|---|---|
| Title ends with "in JavaScript" | Title includes the location ("Akron") |
| Primary keyword = "[concept] JavaScript" | Primary keyword = "[service or page topic] + Akron" |
| Opens with a question hook | The hero states clearly what the page offers, where, and for whom |
| Code example in the first 200 words | Key facts (price, hours, address) or a booking CTA in the first 200 words |
| "What you'll learn" Info box | An at-a-glance facts block (prices, hours, what's included) |
| 1,500+ words | ≥300 words of main content, excluding the header and footer (the skill's 1,500 is a long-form tutorial target) |
| Prerequisites in a Warning box | Links to the next step (booking, visit info, a related service) |
| Related Concepts: 4 cards | Related services or pages section with 3–4 cards |
| Question-format H2 | An H2/H3 phrased the way people actually search ("How much is a haircut in Akron?"). A question like "Ready for the next step?" doesn't count. |

## Site-wide technical issues (outside the 30-point rubric)

These have the most impact and are all cheap to fix. Items 1–4 were confirmed against the live site.

### 1. ❌ Service-page canonicals point to a URL two redirects away (Critical)
`app/(marketing)/services/[slug]/page.tsx:41-43` sets
`canonical: https://theexpshop.com/services/${slug}`, which has no `www` and no trailing slash. On the live site that URL redirects twice:
`theexpshop.com/services/haircut` → 308 → `www.theexpshop.com/services/haircut` → 308 → `www.theexpshop.com/services/haircut/`.
The canonical names a URL that isn't the page, so Google receives conflicting signals for all 9 service pages.

**Fix:** use a relative path. `metadataBase` in `app/layout.tsx:13` already supplies the `www` origin.
```ts
alternates: { canonical: `/services/${slug}/` },
```

### 2. ❌ Every sitemap URL except `/` redirects (High)
`next.config.js` sets `trailingSlash: true`, but `scripts/sitemap.mjs:49` writes URLs without the slash. As a result, 18 of the 19 sitemap URLs return a 308. Search Console reports these as "Page with redirect" and doesn't index them from the sitemap.

**Fix** (`scripts/sitemap.mjs:49`):
```js
<loc>${domain}${route === "/" ? "/" : `${route}/`}</loc>
```

### 3. ❌ FAQ answers are missing from the HTML (High)
`app/components/ui/FaqAccordion.tsx:31` renders an answer only after a click (`{open && <div>…</div>}`). In the live HTML the answer text exists only inside a `<script>` RSC payload. Google indexes the questions but not the answers, which leaves the FAQ page with 66 indexable words.

**Fix:** keep every answer in the DOM and hide it when collapsed. Google indexes content hidden in accordions as long as it's in the HTML.
```tsx
<div className={styles.a} hidden={!open}>{a}</div>
```
Native `<details>`/`<summary>` also works and needs no client state.

### 4. ❌ The LocalBusiness JSON-LD uses a type that doesn't exist (High)
`app/(marketing)/page.tsx:63` declares `"@type": "Barbershop"`, but schema.org has no such type (`schema.org/Barbershop` returns 404). Google won't recognise the markup as a local business. Other problems in the same block:
- `name` is "The Experience Barber Shop" (line 64), which doesn't match the brand name used everywhere else.
- `openingHours` is "Mo by appointment, Tu-Sa 10:00-18:00" (line 77). "Mo by appointment" is not valid syntax.
- `image` is the founder's headshot instead of the storefront or logo.
- `url`, `logo`, `priceRange`, `geo` and `sameAs` (Google Business Profile, Facebook, Booksy) are missing.
- The address and phone are hardcoded instead of read from `app/lib/site.ts`.

**Fix:**
```ts
{
  "@context": "https://schema.org",
  "@type": "HairSalon",            // closest valid schema.org type
  "@id": "https://www.theexpshop.com/#business",
  name: "The Experience Barber & Beauty Shop", // must match the Google Business Profile name exactly
  url: "https://www.theexpshop.com/",
  logo: "https://www.theexpshop.com/assets/images/TheExperienceBarberShopAndSalonLogo.png",
  image: "https://www.theexpshop.com/assets/images/theexperienceshop.webp",
  telephone: "+1-330-475-2522",
  email: EMAIL,
  priceRange: "$20-$40",
  address: { "@type": "PostalAddress", streetAddress: ADDRESS_LINE_1, addressLocality: "Akron", addressRegion: "OH", postalCode: "44308", addressCountry: "US" },
  geo: { "@type": "GeoCoordinates", latitude: /* from GBP */, longitude: /* from GBP */ },
  openingHoursSpecification: [{
    "@type": "OpeningHoursSpecification",
    dayOfWeek: ["Tuesday", "Wednesday", "Thursday", "Friday", "Saturday"],
    opens: "10:00", closes: "18:00",
  }],
  sameAs: [/* GBP URL */, /* Facebook URL */, BOOKSY_URL],
  founder: { "@type": "Person", name: "Deshawn Johnson" },
}
```
The `aggregateRating` block (lines 78–82) can stay, but it won't produce stars. Google treats a business's ratings of itself as "self-serving" and doesn't show them as review snippets for LocalBusiness. If the GBP API is unreachable, the block also falls back to the hardcoded 4.8 / 50.

### 5. ⚠️ Every page shares the homepage's Open Graph tags (Medium)
The root `openGraph` in `app/layout.tsx:30-39` applies to every page that doesn't set its own, which is all pages except Gallery. As a result, every live page has `og:title` "The Experience Barber Shop - Best Cuts in Town" and `og:url` `https://www.theexpshop.com/`. When someone shares `/services/haircut/` on Facebook or iMessage, the preview shows the homepage, and Facebook attributes the share to the homepage URL.

**Fix:** add a small helper and use it on every page. In Next.js, a page-level `openGraph` replaces the parent's object entirely, so the helper must include `type` and `images`.
```ts
// app/lib/seo.ts
import type { Metadata } from "next";
const OG_IMAGE = "/assets/images/theExperienceBarberShopAndSalon3.jpg";
export function pageMetadata({ title, description, path }: { title: string; description: string; path: string }): Metadata {
  return {
    title,
    description,
    alternates: { canonical: path },
    openGraph: { type: "website", title, description, url: path, images: [OG_IMAGE] },
  };
}
```
This adds a self-referencing canonical to every page. Today only the service pages have one, and it's wrong (item 1).

### 6. ⚠️ Inconsistent business name (NAP) (Medium, local SEO)
The business appears under four names:

| Where | Name |
|---|---|
| Titles, header and footer | The Experience Barber & Beauty Shop |
| JSON-LD, franchise page and OG title | The Experience Barber Shop |
| Google Maps embed label (`IFrameMap.tsx:12`) | The Experience Barbershop & Salon |
| Booksy URL slug | lionheart-theexperience_barber-shop |

Pick the exact Google Business Profile name and use it everywhere in code. Ideally, add it as a `BUSINESS_NAME` constant in `site.ts`.

### 7. ⚠️ Orphan pages (Medium)
- `/franchise/` has no internal links pointing to it, only a sitemap entry. The contact page hero mentions "franchise opportunities" without linking.
- `/book/` also has no internal links, because every "Book" CTA goes straight to Booksy. That's fine for conversion. Either link to it from the FAQ answer "How does booking work?" or drop it from the sitemap.

### 8. ⚠️ Footer (Medium)
- The Facebook icon links to `#` (`Footer.tsx:42`). Use the real page URL (and add it to `sameAs`) or remove the icon.
- Quick Links (`Footer.tsx:16-21`) list only 4 of the 9 pages. Add Visit Us, Reviews, FAQ, Contact and Franchise.
- The phone number and email are plain text. Make them `tel:` and `mailto:` links.

### 9. Low-priority technical items
- **Heading order:** on Home, `h4`s follow an `h2` with no `h3` between them (`page.tsx:169,176`). The footer columns use `h4` (`Footer.tsx:50,64,87`). On Book, an `h3` comes before the first `h2` (`book/page.tsx:59`).
- **Render-blocking CSS:** the full Font Awesome stylesheet (about 100 KB) loads from a CDN in `<head>` (`layout.tsx:52-55`) and delays first paint on every page. Use a subset or inline SVG icons.
- **Web manifest:** `name` and `short_name` are empty (`public/site.webmanifest`).
- **Image file names:** gallery files are named `IMG_0165.jpg` and so on. Descriptive names such as `skin-fade-akron-barber.jpg` help a little in image search.
- **Rich results:** add `Service` plus `BreadcrumbList` JSON-LD on service pages, and optionally `FAQPage` on the FAQ. Google currently shows FAQ rich results only for authoritative government and health sites, but the markup still helps machine readers and AI answers.
